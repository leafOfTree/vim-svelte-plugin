1. Introduction                                     *vim-svelte-plugin-intro*

Vim syntax and indent plugin for `.svelte` files. It combines HTML, CSS and
JavaScript syntax and indent in one file, with

- Svelte directives, blocks like {#if}, {#each}, {#snippet} and tags like
  {@html}, {@render}, {@const}.
- Blocks with any syntax by lang="...", like TypeScript, Less, Sass, Scss,
  Stylus, Pug and CoffeeScript, see |g:vim_svelte_plugin_config|. Pug and
  CoffeeScript need vim-pug and vim-coffee-script.
- A builtin 'foldexpr'.
- emmet-vim HTML/CSS/JavaScript filetype detection.

It works if 'filetype' is `svelte`, which is set for `*.svelte` files. As
'filetype' isn't `javascript`, autocmds and settings for `javascript` have to
be enabled for `svelte` manually.

2. Configuration                                   *vim-svelte-plugin-config*

                                                *g:vim_svelte_plugin_config*
g:vim_svelte_plugin_config is the recommended configuration, set before
opening a svelte file. Its default value: >

  let g:vim_svelte_plugin_config = {
        \ 'syntax': {
        \   'script': ['javascript'],
        \   'style': ['css'],
        \   'template': [],
        \ },
        \ 'full_syntax': ['pug', 'coffee', 'typescript'],
        \ 'initial_indent': ['script', 'style'],
        \ 'attribute': 0,
        \ 'foldexpr': 0,
        \ 'open_devdocs': '<F1>',
        \ 'debug': 0,
        \ }
<
syntax
  Syntax list of `script`, `style` and `template` blocks. Other keys are
  ignored, as markup outside <script> and <style> is always the svelte
  template. Each key replaces the default of the same key.
  - lang="..." on the block tag decides the syntax, in double or single
    quotes or without quotes. `typescript` matches lang="ts" and
    lang="typescript", `sass` matches lang="sass" and SugarSS lang="sss".
  - Without lang="...", or if it's not in the list, the first syntax is
    used. <script lang="ts"> is highlighted and indented as the first syntax
    of `script` if `typescript` is not in the list.
  - Syntax plugins need to be installed if not provided by Vim, like vim-pug
    or vim-coffee-script.
  A string can be used for a list with one item.

full_syntax
  Syntax whose files are loaded from all of 'runtimepath', including
  plugins. Others are loaded only from $VIMRUNTIME/syntax, ~/.vim/syntax
  and $VIM/vimfiles/syntax, or from all of 'runtimepath' if not found there.
  Vim may be slow when loading many syntax files.

initial_indent
  Block tag, syntax or tag.syntax like `style.scss` to indent one level
  initially.

attribute
  1 to highlight the key of svelte attributes like `on:click` and
  `bind:value` as |hl-Type|, and their value {...} as normal text instead of
  string.

foldexpr
  1 to use the builtin 'foldexpr' with 'foldmethod' set to `expr`.

open_devdocs
  Key mapping to search https://devdocs.io, see
  |vim-svelte-plugin-mappings|. Set to '' to disable it.

debug
  1 to echo debug messages in |:messages|. Useful to debug unexpected
  indents.

Example: >

  let g:vim_svelte_plugin_config = {
        \ 'syntax': {
        \   'script': ['javascript', 'typescript'],
        \   'style': ['css', 'scss', 'sass'],
        \ },
        \ 'foldexpr': 1,
        \ }
<

  g:vim_svelte_plugin_load_full_syntax  `full_syntax` with html, css,
                                        javascript, less, sass and stylus
  g:vim_svelte_plugin_use_pug           `pug` in `syntax.template`
  g:vim_svelte_plugin_use_coffee        `coffee` in `syntax.script`

  g:vim_svelte_plugin_use_less          `less` in `syntax.style`

3. Functions                                    *vim-svelte-plugin-functions*

As there is more than one language in a `.svelte` file, different mappings,
completion and local options may be wanted by tags or subtypes, the current
language.

                                                             *GetSvelteTag()*
GetSvelteTag([{lnum}])
  Return the tag at line {lnum}, or the cursor line: one of `'template'`,
  `'script'`, `'style'`, or `''`. Example: >

  autocmd FileType svelte inoremap <buffer><expr> : InsertColon()

  function! InsertColon()
    let tag = GetSvelteTag()
    return tag == 'template' ? ':' : ': '
  endfunction
<
                                                         *GetSvelteSubtype()*
GetSvelteSubtype()
  Return the subtype at the cursor line, like `'html'`, `'javascript'`,
  `'typescript'`, `'css'`, `'scss'`.

                                                    *OnChangeSvelteSubtype()*
OnChangeSvelteSubtype({subtype})
  If defined in your vimrc, it is called whenever the subtype under the
  cursor changes. Example: >

  function! OnChangeSvelteSubtype(subtype)
    if empty(a:subtype) || a:subtype == 'html'
      setlocal commentstring=<!--%s-->
    elseif a:subtype =~ 'css'
      setlocal commentstring=/*%s*/
    else
      setlocal commentstring=//%s
    endif
  endfunction
<
==============================================================================
4. Mappings                                      *vim-svelte-plugin-mappings*

<F1>
  Search https://devdocs.io for the word under the cursor, or the selected
  text in Visual mode. Change the key by `open_devdocs` in
  |g:vim_svelte_plugin_config|.

If matchit is loaded, |%| also jumps between tags and svelte blocks like
{#if}, {:else} and {/if}.

==============================================================================
5. Avoid overload                                *vim-svelte-plugin-overload*

Most delays come from loading syntax files of many languages.
`b:current_loading_main_syntax` is set to `svelte` while loading, which can
be used as a condition in syntax files that load others. For example, the
builtin sass.vim and less.vim load css.vim, which this plugin has loaded: >

  if !exists("b:current_loading_main_syntax")
    runtime! syntax/css.vim
  endif
<
